# 跨页流程与校验

本文同步 v1.0.1.7 的订单与柜机主链，替换旧订单 Mock 旅程。业务 authority 为治理仓 [Feature](../../../xingyu-governance/docs/rental/features.md) 和 [Flow](../../../xingyu-governance/docs/rental/flows.md)；实际 API、数据约束及权限以当前服务端合同为准。

## 角色与旅程

游客可浏览公开供给；租赁、订单和柜机操作要求当前有效小程序会话。订单参与关系、资产归属及服务端动作许可决定可操作性，路由参数和页面视角不授予权限。

|流程|成功依据|异常与恢复|
|---|---|---|
|官方设备入柜→上架|正常入柜登记产生 placement 和 DORMANT 凭证；上架是独立动作|RFID、格口与资产身份必须一致，不能把柜在线当实物入柜|
|设备详情→日期→报价|官方固定柜机，个人固定快递；日期只到日，开始不早于当天，结束及最短租期合法|错误弹窗说明原因；报价读取最新服务端结果，不能用客户端金额代替|
|准备→实名/协议→正式订单|冻结条件、保存实名、协议明确同意、正式确认后进入待支付|未知准备结果保留原请求，通过 lookup 恢复，不创建替代订单|
|支付→待交付|原支付经可信通知/查单消费成功；官方本单原凭证激活|预支付、wx.requestPayment 返回和页面跳转均不是业务成功；重复通知幂等|
|订单看码→扫柜scene→手输码|本人、原订单、当前柜、有效码与租期窗口全部合法后建立原任务|错误码/错柜/他人码统一拒绝，不泄露关联订单；填满不会自动开柜|
|立即弹窗→实际开门→取物关门|弹窗自动读取原任务；可信门关且目标已离柜后任务 SUCCEEDED、凭证 CONSUMED、订单 IN_USE|开门不等于完成；慢响应/断网继续核实，不能再次发送开门命令|
|个人快递交付|允许的发货记录与收货确认形成原订单交付事实|不得借用柜码流程、柜门反馈或旧面交/跑腿入口|
|归还→实收→核费|官方可信入柜观测或个人出租方实收形成实物归还；材料可独立提交，官方 FINAL 核费|照片上传、关门或点击按钮各自不代表退款到账；无充电照前置或“三次查询即完成”|
|退款/补缴→完成|原资金记录及服务端终态，收益与资产重新上架各自遵守当前规则|未知资金查原记录，不伪造成功、不重复付款；实物实收可先释放占用|

本期不提供小时租、面交/跑腿、续租、免押、人脸模拟或租客争议反提方案。其他模块的功能与未验边界在各自文档记录，不能用其旧 Mock 描述当前订单能力。

## 参数与校验

confirm 接收 deviceId/asset_id；order-detail 和 contract 接收原 orderId/id。柜体 scene 进入 cabinet-code，六位码由本人手动输入，保留前导零。原 taskId 用于 cabinet-open 恢复，不依赖旧 EventChannel 回传开柜授权。订单/任务都要重新校验当前账号。

金额以整数分传递，页面只格式化。客户端日期和必填校验用于及时反馈，服务端仍验证报价、库存、权限、窗口、版本和幂等。允许金额和租期以本单冻结条款及当前动作返回为准，不沿用旧 fixture 的默认押金、小时计价或优惠规则。

## 自动等待

取件提交立即弹窗，正常流程不要求手动刷新。监控顺序读取同一任务；前台慢响应降低频率，断网给出继续核实提示，页面隐藏/卸载或账号变化停止旧响应写入。达到等待上限后保留原任务，允许继续核实/联系客服。服务端可信终态才显示成功；查询不顺便退款、验收或结算。

## 返回与恢复范围

准备单、支付和柜机未知结果必须保留原意图并查询原记录；明确拒绝的表单输入可以更正。业务事实由服务端保存，本地 busy 只抑制本页重复点击。页面/账号切换隔离旧数据；进程恢复能力以各 API 意图存储和服务端 lookup 为准，不承诺所有临时草稿跨设备恢复。

归还材料与实物分离，已有材料、已提交记录和本地未提交草稿分别处理。无可信实收时不手工置归还成功；异常通过原生客服和官方当前流程处理。

## 验证入口

当前实现入口为 shared/api/rental-api.ts、shared/interaction/rental-page-state.ts、cabinet-task-monitor.ts、shared/presentation/checkout-term.ts 及各页面。测试定位到 tests 中对应 rental、cabinet、checkout 用例与 API tests/integration；正式结果消费本版 Change 的 Docker S3 和官方开发者工具规范回执。

本次指定链路另有真实千鸣开门、RFID 离柜与关门证据；微信支付使用离线回调模拟，未执行真实资金、相机扫码、真机或平台发布。静态说明不是运行验收。
