# 柜机、归还与售后

当前实现：v1.0.1.7，订单和取还件接入真实开发 API。业务状态取服务端回读；微信真实资金和正式发布不在本次验收范围。订单与取件验收见治理 Change `XY-20261006-37d27e06874f41379ba922c9b19d6ed3`；归还及其 UI 验收见 `XY-20261008-83dfa8ec5750443297f5c0e8031e3919` 的 S3/S4。本页描述当前行为，不代替运行证据。

<a id="mp-cabinet-detail"></a>

## MP-CABINET-DETAIL 柜机发现与归还选格

`pages/cabinet-detail/index?id=…` 从柜机列表进入，读取柜机、可租商品及位置，支持商品详情和地图导航。归还模式额外携带 `mode=return&orderId=…`，读取本人原订单、允许柜格及已有归还任务。选择格口只更新本页选中项；用户明确确认后才预留并按允许动作开门。未知结果恢复原任务，不能另换格重复开门。

扫描柜体小程序码的取件落地页为下述 `cabinet-code`，其页面同时展示该柜详情和取件码输入。扫码只确定柜，不携带订单或格口授权。

<a id="mp-cabinet-code"></a>

## MP-CABINET-CODE 柜详情与取件弹窗

路由 `pages/cabinet-code/index?scene=cab_…`。输入当前账号订单中的六位码；保留前导零，填满不自动提交。订单详情负责查看或复制码，本页不自动读取或填充本单码。

| 交互 | 校验与反馈 |
| --- | --- |
| 打开柜详情 | 校验 scene、登录和柜机可用性；展示名称与地址，帮助用户确认到达正确柜机 |
| 确认并开柜 | 点击后立即显示进度弹窗；原码解析预留成功且允许 OPEN 才发一次开柜请求；等待期间防止重复提交 |
| 码不可用 | 统一错误弹窗，不泄露他人订单；点“重新输入”回到输入位置。本人有效码但未到租期可告知具体开始日期 |
| 等待开门 | 自动读取同一任务；ACCEPTED 仅表示请求受理，不能显示门已打开 |
| 门已打开 | 依据该任务可信门态及时间，显示格口并提示“取出设备，关好柜门” |
| 核实取件 | 用户不必点击刷新或确认关门；Worker 回读门态和 RFID，弹窗自动同步 |
| 取件完成 | 仅任务 SUCCEEDED 后展示成功，可查看原订单或完成；客户端不写成功状态 |
| 较慢、断网或后台返回 | 保留原任务与幂等意图，只读取原结果；隐藏/切号/离开停止当前读取，返回同账号恢复。不自动再次开门 |

取件窗口由服务端校验本单固定租期。已知任务正常每 2 秒串行 GET，等待超过 60 秒或读取失败后每 5 秒；单轮最长 10 分钟，之后明确提示继续核实或联系客服。持续等待不制造第二条开柜命令。产品实现见 `shared/interaction/cabinet-task-monitor.ts` 与 `shared/presentation/cabinet-feedback.ts`。

<a id="mp-cabinet-open"></a>

## MP-CABINET-OPEN 原任务结果与恢复

路由携带 `taskId`。取件正常操作留在柜详情弹窗，本页用于重进原任务，自动回读并展示门态、设备识别和完成时间。待预留任务可返回柜详情继续明确开柜；完成只导航原订单。归还任务保留原查询能力。它是实际任务结果页，不是旧兼容转接页。

<a id="mp-return-submit"></a>

## MP-RETURN-SUBMIT 归还与材料

路由 `pages/return-submit/index?orderId=…`，读取本人当前订单、归还记录和服务端 allowed_actions。官方固定柜机归还，个人固定快递；不允许任意改成跑腿或面交。

凭证按订单冻结模板逐槽展示、校验和保存，使用真实素材 API，未 READY 不可正式绑定。官方 PRE_RETURN 必需槽位齐全后才能选柜、预留及首次开门；个人快递可以先寄回。已保存项在服务端允许的阶段可更换，服务端原子切换当前项并保留旧修订；核验期间冻结前置凭证，FINAL 后全部只读。AFTER_OPEN 入柜照片缺失不阻止已开门后的可信实收，但阻断最终核费，允许随后补齐。

“查看示例”与槽位标题同排，以较小字号展示，使用冻结到订单的 OSS 图片或视频。上传区保持协调比例，已上传项提供预览和更换；原生选图临时隐藏页面后允许继续上传，真正离页、切号或卸载使迟到结果失效。

快递按当前归还地址版本确认后登记运单；更正需说明，不能伪造签收。柜机可信收回与最终审核、退押各自有独立状态；“已入柜”不等于订单已完成或押金已到账。

<a id="mp-cabinet-return"></a>

## MP-CABINET-RETURN 本单柜机归还

路由 `pages/cabinet-return/index?orderId=…`。展示原任务的开门、放物拍照、关门、待确认、核验及结果状态。归还柜和格口在前序页面选择；原任务未知时只查询原结果，不重复开门。

轮询静默更新变化字段，不切换整页加载态或重绑未变化媒体；门关且 RFID 一致、进入待确认时停止轮询。用户明确点击确认归还后，先读取同一任务最新 ETag 并校验归属及允许动作，再提交一次确认；412 提示重新核对，不自动重试写入。确认后由服务端查询原格口，同一次新响应的门态和 RFID 满足条件才可信实收。没有独立设备在位或充电检测；RFID 不一致显示归还失败并提供原生客服入口，未知结果保留原任务。

成功后仍分别展示材料和审核状态；材料缺项可继续补齐，实收不因补图回退。租期超时不阻断归还，超期、损失及应退或应补在后台退押核费环节处理。

<a id="mp-dispute"></a>

## MP-DISPUTE 旧争议入口

当前页面为不可用占位，旧 Mock 的方案协商和裁决动作未接入本版真实订单，不构成本期能力。现行归还审核、一次退押/补缴按原订单及后台审核入口办理。客服为微信原生 contact，不替代任何业务审核或状态变更。
